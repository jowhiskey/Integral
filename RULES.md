# RULES.md — the live behavior-rule file (agent-owned)

## What this file is

The single source of truth for **editing behavior as implemented** — every input, every caret position, every structure, as ruled by the owner. Seeded from the master interaction contract's implemented status quo (2026-11-11, develop past the DOM-rework PR #5, the streamline pass, and the LF unification) and maintained by the coding agent from here on.

**Ownership + update protocol**

- **The coding agent owns this file.** Unlike `AGENTS.md` and `docs/context/*` (frozen chat-side mirrors you never edit), you update this file directly: every behavior ruling the owner gives — a chat answer to a stop-and-ask, a live-check ruling, a dogfood-cluster triage decision — lands here as part of the same commit that implements it.
- Entry format: the rule (what happens, concretely), the source (the owner's words, condensed), the date, and the affected labels. Update the rule text where a new ruling supersedes an old one — this file always states the CURRENT rule, with the change noted at the end of the entry.
- **Behavior nobody has ruled = stop-and-ask.** Never design behavior silently, never copy behavior from another editor "because it makes sense". The answer goes into this file once given.
- The owner's chat side fetches and diffs this file against the master contract at sync points; contradictions surface to the owner. Wording drift is expected; semantic drift is not.

**Precedence (iteration phase, from 2026-11-11):** for editing-BEHAVIOR questions this file supersedes `docs/context/interaction.md` and the behavior passages of `docs/context/editor-spec.md`; those mirrors are frozen during the iteration phase and regenerated at reconciliation. AST/contract questions (node shapes, JSON envelope, vocabulary) still go to `docs/context/editor-spec.md`.

**Label scheme:** T = typing, N = navigation, C = clicks, D = deletion, U = undo/redo, K = special keys, OA- = owner amendment (live rulings during implementation). S-numbers are historical scenario IDs from the original interview, kept where the test suite cites them.

## Typing (T)

- **T1 — Rows are literal, text-like sequences.** A typed token appears at the caret; nothing restructures at edit time. Operators insert alongside (`a+b+|c` + `+` → `a+b++|c`), before an existing operator (`a|*b` + `−` → `a−|*b`), at row start (leading `+` allowed: `|a` + `+` → `+|a`), at row end, and from empty (lone `−`). Caret lands directly after the inserted token. `*` displays as ×.
- **T2 — No in-place operator replacement.** Operator edits = delete + retype; typing behaves "as in any text editor". Select-then-type-over = future selection feature.
- **T3 — Symbols and numbers are multi-character, text-like tokens.** Same-type input glues onto the token at any caret offset. Different-type input splits the token at the caret and inserts the matching node between the halves (`a|b` + `+` → `a+|b`). **Digit-glue (OA):** a digit typed after or inside a symbol joins the SYMBOL NAME (`x` + `1` → `x1`; `a|b` + `5` → `a5b`) — number nodes only form where no symbol precedes. A letter typed inside a number splits it — the pieces read as implicit multiplication (the `5·x·3` shape). A letter before a number starts a juxtaposed symbol. **Space inserts a node boundary** (S-021/S-022 mechanic, unchanged): inside a token it splits it; at an edge it separates the next same-type input (needed only for same-type adjacency, e.g. two symbols in a row). Space-forced number-number adjacency is FORBIDDEN — see S-098 under Evaluation. The gap's RENDERING follows OA-seam-family (Navigation): S-021's old "Space leaves no visible mark" clause is superseded — an illegal split's gap renders visibly wide and red.
- **T4 — Numbers.** Digits extend at the caret. `.` joins a number as decimal point. A dot that CREATES a new number auto-prefixes zero (renders `0.`), caret inside, after the dot. **In-progress trailing decimal (OA-dot):** `5.` is storable and renders with the caret after the dot (additive `dot?: true` on the num node); a digit after the dot extends the value and clears the flag; a second dot is a silent no-op; blur persists it; it EVALUATES as its numeric value (`5.` = 5).
- **T5 — Function names by paren conversion.** Typed letters build an ordinary symbol (T3); `(` after a symbol whose name matches a known function converts it into the atomic head, opens the argument list, and adds the closing fence immediately — but ONLY when no elements stand to the right of the caret (T10). Caret inside at the first argument start. The `(`-press + conversion is ONE undo unit.
- **T6 — Parens never auto-wrap.** `(` creates a group with BOTH fences at the caret; content to the left stays outside (implicit-multiplication reading).
- **T7 — Structure keys `/` and `^` create 2D structures with □ slots (OA-both-halves).** At an interior caret the token SPLITS: left-of-caret content becomes the numerator/base, right-of-caret content the denominator/exponent (`12|3` + `/` → frac(12,3); `ab|c` + `^` → pow(ab,c)). Token-end caret → the ordinary whole-node grab + □ (`(a+b)|` grabs the whole group). Offset-0 caret → □ left slot + the token in the right slot. No token → □/□ with the caret in the numerator. The caret lands at the START of the right slot. Split + grab + fill = ONE op = one undo step. **At an edge station of an ILLEGAL implicit pair's gap the structure key grabs BOTH cells across the gap** — the pair collapses into the structure, the caret keeping its side of the splice (left-edge press → the left slot's end, e.g. after the grabbed "a" in the numerator; right-edge press → the right slot's start) (OA-seam-landings, rec-mwcmo3bd-6 / rec-mwcmq3pj-7). A legal pair's seam keeps the seam reading (left cell only).
- **T8 — Dead keys (OA-dead-key + OA-one-shot).** ANY keydown with `key === 'Dead'` arms a ONE-SHOT power pending (layout-independent). The pending survives until the very next key press: a printable character resolves it (the character lands in the exponent); Space yields the empty □ exponent; EVERY other input (Backspace, arrows, click, blur, any non-printable key) discards the pending and then does its ordinary job — the editor behaves exactly as if `^` was never pressed. A dead-key re-press re-arms (idempotent). Never serialized, never logged, no tree change while pending. **Firefox/Windows (landed):** no composition events fire; the composed output rides the NEXT keydown as a two-character key value (`key="^2"`) — an armed pending consumes and composes that key value. **Amended 2026-11-11 (A5):** the `=` key is the ONE printable exception — an armed pending + `=` DISCARDS the pending and the `=` does its ordinary job (the root-row assign); an exponent never receives the `=` (the pre-ruling "resolve" was a settle-machinery artifact).
- **T9 — Root/subscript insertion vocabulary (machinery; the suggestion box + palette UI are a future feature).** `insertRoot` forward-grabs (OA-root-grab): content right of the caret goes under the radical, caret at the radicand start; nothing right → □ radicand; at a dangling operator the pending-operand cell is filled; `mroot` = the same grab plus a □ index slot. `insertSubscript`; sub labels are keyboard-typable via an additive token-caret field (`label: 'base'|'sub'`, editor state only, never serialized). One op = one undo step each. **`_` is a T9 entry key (2026-11-13, rec-mwesdgob-6):** the `_` keydown (Shift+Slash on US layouts) classifies to the subscript insertion trigger — the key event only, the insertion behavior unchanged; it is not a typing token and closes the typing run like any structure insertion.
- **T10 — Function insertion is context-dependent.** With elements to the right of the caret, the head inserts BARE over the existing content (`sin(|a+b`, no closing fence added) — a function never closes over content that was not in scope.
- **Units (S-051/S-104 + OA rulings).** A letter run directly following a NUMBER converts into an attached unit ON LEAVING the run (any non-letter key, arrow, click, or blur — never letters, never undo/redo; longest match wins). Unknown runs stay ordinary symbols. Attachment is number-followed-only (OA-unit-attach): a run that does not directly follow a number (e.g. after a group or fraction) stays a symbol. A Space between the number and the run does NOT block attachment (OA-unit-space). Units are GRANULAR: editing works letter-wise inside the label; on leaving, a still-known run stays a unit, an unknown label reverts to `[num, sym]`; a digit typed inside the label reverts the run; Space inside a label permanently breaks the run. An emptied label is not stable (OA-empty-unit): the value promotes bare and deletion continues into the digits (`50mm` → `50m` → `50` → `5`). A unit has ONE seam at its right edge (OA-unit-single-seam); the next typed key decides the channel: digit or `.` → the value; letter → the label (recheck on leaving); operator → an ordinary glyph insert after the unit.

## Navigation (N)

- **N1 — Tokens step character-wise** (letters, digits, decimals included).
- **N2 — One shared gap station.** The position between two tokens is ONE station, never two. **Bifurcation (OA-seam-family):** the glyph-less gap between two cells of an implicit row splits on the `implicitPairLegal` predicate — a LEGAL pair is ONE station at the gap (the `50|mm` pattern generalized); an ILLEGAL split (S-098 num-num, symbol-before-X, fn/unit-before-X) keeps BOTH edge stations, each reachable and a distinct state. See the OA-seam-family entry below.
- **N3 — Formula ends:** → at the very end / ← at the very start = silent no-op.
- **N4 — Horizontal arrows stay at the visual level.** → at a slot's end EXITS the structure and lands after it in the row — it never dives into a sibling slot. Confirmed exits: numerator, denominator, exponent, group content past the fence, last function argument.
- **N5 — Horizontal entry points.** → into a fraction from the left → the numerator start; ← from the right → the NUMERATOR end (the fraction's horizontal interface is the numerator on BOTH edges — the denominator is reachable only vertically or by click); ← at the denominator start exits past the whole fraction; → at a power's base end → exponent offset 0; ← at exponent offset 0 → the base end; ← from the right of a power → the exponent end. The mroot index joins the horizontal step-through (OA-index-horizontal).
- **N6 — Vertical arrows use caret memory.** Per-region store, written on vertical exits (including in-token index), read on vertical arrivals, stored-wins-if-it-resolves, validated on use. **Nesting ENABLED (OA-vmem-nesting):** vertical descents follow the nesting chain into remembered nested positions (big numerator → nested numerator only, never skipping into the nested denominator). **The ONE clear:** a ←/→ exit from a structure wipes that structure's layer memory; vertical exits and everything else never clear. ↑/↓ on flat rows = silent no-op. Memory serves vertical keys only — clicks never read or write it.
- **N7 — Function arguments read in order:** → at an argument's end steps past the comma into the next; at the last argument it exits past the closing fence.
- **N8 — Empty slots are normal slots:** → exits the structure; the □ stays behind as the affordance.
- **OA-visual-trumps (the master rule).** The caret geography follows the RENDERED structure, not the AST shape. Engine caret states map 1:1 onto visually distinct positions — never two rest-states for one visual spot, never a visible spot without a state; the visible caret position and the engine caret position are the same thing at all times (no paint-only fixes; clicks, typing, and arrows address the SAME state inventory). A fenced group's content-end and post-fence positions are TWO positions (`1/(a+b|)` vs `1/(a+b)|`); a bare operator row in a slot has exactly ONE end position. **Nav corollary:** one ←/→ press is never consumed by an invisible state transition — one press = one visible movement between distinct positions, or a defined no-op at the formula ends; no horizontal transition may exist whose origin and result paint at the same visual spot.
- **OA-token-end.** Typing leaves the caret at the natural end of what was typed: in-token end for tokens (letters, digits, unit labels, sub labels); the after-seam for operator glyphs and structure keys. Never a whole-node caret on the freshly typed token.
- **OA-vertical-default.** A no-memory vertical arrival rests at the END of the target region's content, diving through wrappers (a denominator holding a fenced group → INSIDE the fences, after its last character). When the region's content ends WITH a structure, the rest is the seam AFTER that structure, never on it. A no-memory vertical rest in front of the close paren = the content end (intended, owner-confirmed).
- **OA-lone-root-stations.** A lone fraction/root/power standing as a bare non-row region gets border stations (additive node-caret `side: 'left'|'right'`, guarded to whole containers): re-entry, exit, the formula ends, and D5 highlight-from-outside all work there; the border spots are distinct visual positions before/after the structure.
- **OA-flank-stations.** The positions directly against a MID-ROW structure's left and right edges (between the `+` and a fraction in `x + 1/2 + y`) are real restable, insertable stations; D5 highlight-then-delete is reachable from the right-edge station.
- **OA-fence-flank.** Fenced groups have BOTH outside flank stations — left of the open paren and after the close paren. Fence glyphs delete as movable tokens from their adjacent stations (see D).
- **OA-seam-family (2026-11-11, owner ruling; closes Known-open I-22 (b)).** The glyph-less juxtaposition gap between two cells of an implicit row bifurcates on the EXISTING `implicitPairLegal` predicate — this refines its consumption; the predicate itself is unchanged.
  - **(1) A legal implicit pair (number-before-X: `5x`, `5(a+b)`, `5√2`, incl. implicit subrows nested in explicit rows) renders ONE caret station at the gap** — OA-unit-single-seam generalized: the seam paints midway (OA-unit-seam-paint generalized); the walk has ONE stop across the gap (→ from the number's end skips past the seam — the `50|mm` pattern generalized; ← likewise; both sides resolve to the same station). **The typed key decides the channel:** digit/`.` → the number side; letter → the non-num side (glue into a symbol, or seed a new symbol before a group/structure); operator → an ordinary glyph insert between. Legal pairs render glyph-less with plain spacing — NO seam marker, in BOTH renderers.
  - **(2) An illegal split (number-number S-098, symbol-before-X, fn/unit-before-X) keeps the TWO edge stations** — the gap renders VISIBLY WIDE so the two stations are two distinct visual spots (OA-visual-trumps satisfied by prominence, not merging) **and the seam marker turns RED** (the `.integral-seam` mspace is the wide red carrier, width 0.5em, background #c62828, explicit height/depth — supersedes S-098's quieter tint: an illegal split is an error state and renders as one).
  - **(3) The unit→symbol conversion double seam resolves by construction** — the post-conversion pair is a legal implicit pair → the single seam; the unit node's own seam is unchanged (OA-unit-single-seam).
  - **(4) SPACE-to-split is UNTOUCHED as an input mechanic** (S-021/S-022, the `boundary` flag, same-type separation): a Space-created and a directly-typed juxtaposition are the same stored state and get the same seam treatment — with S-021's "Space leaves no visible mark" clause SUPERSEDED by (1)/(2): the two-station gap renders visibly wide and the gap is a deletable object per (6).
  - **(5) Typing an operator at EITHER station resolves the gap:** red/wide gaps never block input — the ordinary T1 glyph insertion at either station binds the sides and the gap state (marker, stations) is gone (`5 5` + `+` → `5+5` legal; a legal pair's seam + operator → the explicit row).
  - **(6) The gap is a DELETABLE object** (partially supersedes D2's left-consume at the two-station juxtaposition seams): BS at the right-edge station / Del at the left-edge station deletes the GAP and merges the sides; the outward directions (BS at the left station / Del at the right station) keep ordinary character deletion; the caret lands at the splice offset (the boundary position inside the merged token). The LEGAL single seam KEEPS its adjacent-characters behavior (the D2/D1 mirror per OA-unit-single-seam) — no gap object exists there. **Merge table:** (num,num) → digit concatenation into ONE number (`5 5`→`55`; `5`+`0.5`→`50.5`; `5.`+`5`→`5.5`; `5`+`5.`→`55.`); (sym,num) → digit-glue into the name (`x 5`→`x5`); (sym,sym) → letter glue (`x y`→`xy`); glyph-glyph → the adjacent-glyph row state (`+ *`→`+*`, the S-001 typing shape); legal mixed pairs → the implicit multiply, the tree unchanged (no gap deletion there). **Merge guard — the deletion fires IFF the merge lands on a legal state, otherwise a SILENT no-op:** (a) both sides decimal (`5.5`+`0.5` — not a number; a SPLIT number merges back exactly: `50.5` split → `5`+`0.5` → `50.5`); (b) symbol + decimal number (the dot cannot join a name); (c) mixed pairs with no fusion and no legal multiply (`sym|group`, `sym|structure`, `fn/unit|X`, `group|num` — the merge target IS the refused implicit pair). In the refusing classes the red gap is UNDELETABLE — resolved only by operator insertion (5) or deleting a side. One op = one undo unit; undo byte-restores the unmerged state.
  - Clicks: a gap-region click maps to the single seam station (legal) or the two edge stations by half (illegal). Labels: N2, T3, C1, D2, S-098, S-021, paint.
- **OA-sub-right-exit (2026-11-13, rec-mwesfxub-7 — closes the N-12 trap).** At a row border with no glyph zone (the sub is the row's last cell; implicit rows render no glyphs), ArrowRight from the script label's end rests at the row-end seam BEHIND the sub (`row [] #2`) — the D5 highlight's seat — never clamps back onto the script end (which the climb's twin collapse would produce as a no-op). Mid-row (a glyph zone) keeps the R-flank station (`node side:'right'`); a lone sub at the root keeps the N3 no-op. Labels: N4, N3, OA-flank-stations, D5.
- **OA-seam-landings (2026-11-11, dogfood cluster `integral-testlog-cluster-2026-11-11T21-35-20-171Z`; rec- ids cited at the pins in tests/seam-family.test.ts).** Twin canonicalization + landings around the pair gap:
  - The row seam at an implicit pair gap whose right cell is a TOKEN is that token's offset 0 — one → press from it skips past (rec-mwcmu8sa-8: no mechanical no-op step); ← from it reaches the left edge station. At the row END of an implicit row with a token last cell, the seam IS the token's in-token end — ← steps into the token (rec-mwcmzfd6-b: the caret is never locked there).
  - Crossing a pair gap whose right cell is a CONTAINER rests at the gap's right edge (the row seam, in front of the structure) before diving — the legal pair's seam and the illegal pair's right edge alike (rec-mwcmb8ok-1).
  - BS emptying a cell whose LEFT neighbor in an implicit row is a filled token lands at that token's right edge ("after the 5" / "after the a"), not the row seam (rec-mwcm8ovm-0, rec-mwcmjcwr-3, rec-mwcmw6mq-9).
  - The glyph-bond landing (D2's binding-glyph delete and OA-del-glyph's forward mirror) rests at the RIGHT edge of the new implicit gap — the right cell's offset 0 for a token, the row seam for a container — SUPERSEDING B-33 (2)'s left-operand-right-edge landing now that the pair's two gap edges are distinct stations (rec-mwcmhuyq-2).

## Clicks (C)

- **C1 — Nearest-edge principle.** A click resolves to the nearest legal position: inside a slot, the nearest character edge of that slot's content (character-wise for numbers and symbols, NOT always the end); operator glyphs map to the shared gaps flanking them; past a slot's content → its end; container edge zones → the structure's own edge station. **Glyph halves (OA-glyph-click-halves):** a click on an operator glyph's LEFT half resolves to the position BEFORE the glyph; the right half keeps the behind-the-glyph shared gap. Container fence glyphs resolve via the fence element map (a dangling fence token's own uid wins as a node hit); function name heads via the fn-head map; sub label elements are clickable.
- **C2 — The □ is the empty slot's click target:** clicking the □ (or its slot area) enters the slot, caret before the □.
- **C3 — The fraction bar maps to the flanking row gaps:** 50/50 split — left half → the gap before the whole fraction, right half → the gap after it. The bar never enters num/den.
- **C4 — The function head is an atomic unit** (`sin(` including the open paren). Clicking the head's name area → caret right after the open paren (first argument start); the head's left edge → the gap before the head. The closing paren — of a function AND of a plain group — is a MOVABLE token (deletable, insertable elsewhere). A typed `)` completes the INNERMOST unclosed open fence to its left; with nothing unclosed it inserts as a literal dangling close paren (error-annotated, storable; evaluation refuses via the structural gate). A re-typed `)` restores the function/group it belonged to.
- **C5 — Background snap:** a click hitting no glyph snaps to the nearest legal position (past the end → the formula end; empty formula → the single start position).
- **C6 — Double-click selects the clicked token/structure** — deferred to the future selection-ranges feature.
- Clicks never read or write the vertical-position memory; click-only moves produce ZERO undo-log entries.

## Deletion (D)

- **D1 — BS/Del in tokens: one character, letter-wise** (symbols, numbers, unit labels, sub labels). BS deletes the character left of the caret, caret at the resulting offset; Del is the forward mirror (removes the character right, caret stays). Converted tokens stay atomic at their boundary (the function head goes whole); attached units are GRANULAR instead (letter-wise, see T-units).
- **D2 — BS at gaps consumes the left-adjacent token's LAST character** (glyph-free gaps, dangling operators included: `−x+|` → `−x|`). An atomic left-adjacent token goes whole. BS at the gap BEFORE a function is the ordinary gap rule — it deletes whatever stands to the left, never the function. **Supersession (OA-seam-family (6)):** at the two edge stations of an ILLEGAL juxtaposition gap, BS at the RIGHT-edge station deletes the GAP itself (the merge per the merge table + guard in the OA-seam-family entry), not the left character; BS at the left-edge station keeps the ordinary left-consume. The LEGAL single seam keeps this D2/D1 mirror unchanged. **OA-glyph-delete:** BS at a BINDING-GLYPH station (an operator followed by its filled right operand) deletes the GLYPH; the freed cells bond into an implicit pair (`x + |1/2` → `x 1/2`), uniform across right-cell kinds. **Landing:** the caret lands at the RIGHT edge of the new implicit gap — the right cell's offset 0 for a token, the row seam in front of a container (`x+|1/2` → BS → `x|1/2` with the caret in front of the fraction, never inside the bonded structure). Supersedes B-33 (2)'s left-operand-right-edge landing (OA-seam-landings, rec-mwcmhuyq-2).
- **D3 — Ctrl+BS / Ctrl+Del: split semantics.** Ctrl+BS deletes everything left of the caret WITHIN the token (the whole token only at offset = length); Ctrl+Del is the forward mirror (everything right within the token; the whole right-adjacent token at a gap).
- **D4 — Empty formula:** BS and Del are silent no-ops.
- **D5 — Highlight-then-delete, fenceless 2D structures only** (fraction, root, subscript, power), from OUTSIDE stations only: BS at the station immediately after the structure highlights the entire structure red (a TRANSIENT UI state, never an undo entry); the next BS deletes the whole structure WITH its content, leaving the pending null (OA-pending-null — the left operator keeps dangling: `x + 1/2` → highlight → BS → `x + |`). BS from INSIDE is always char-wise → □ → unwrap (D6); the highlight never fires from inside. **OA-del-highlight (2026-11-13, rec-mwe0xrj1-0) — the forward mirror:** Del at the station immediately BEFORE the structure (the row seam facing it, or its left flank) arms the SAME red highlight; the next Del deletes the structure WITH its content (pending null at an args cell). Same transient lifecycle (U2: the arm never logs; any non-confirming input clears it). Fenced containers and nested rows right-adjacent keep the named no-op; the fn head stays atomic. Labels: D5, OA-del-glyph, delete.
- **OA-sub-label-empty (2026-11-13, rec-mwesfxub-7).** Shrinking a sub label (base or script) to the EMPTY string by BS/Del is a legal char-wise deletion — the empty label is the incomplete state rendering □ (OA-sub-placeholder); only a shape-breaking NON-empty remainder is a silent no-op. The next BS at the empty script takes the S-102 unwrap (the sub dies, the base stays as a symbol); at the empty base the baseless sub dies outright. Labels: D1, D6, T9, OA-sub-placeholder.
- **OA-del-glyph — forward Delete at operator gaps removes the glyph.** Del in a non-trailing pending cell removes the dangling glyph to its RIGHT (`|x+1/2` → Del → `|+1/2` → Del → `|1/2`); Del at the before-glyph token-end station removes the glyph ahead and bonds the cells (`x|+1/2` + Del → `x 1/2`, caret at the gap's right edge — uniform across right-cell kinds, per OA-seam-landings rec-mwcmhuyq-2); Del at a structure's right flank bonds the cells; at FILLED seams Del keeps the D1/D3 mirror (the glyph there is Backspace's).
- **D6 — BS at a □ unwraps and PROMOTES.** The structure dies; the surviving sibling content splices inline at the structure's position, caret at the splice point (`x + frac(□,2)` → BS → `x + |2`; `a^□` → BS → `a|`). Both slots empty → outright death, nothing promoted. The denominator mirror (numerator promoted), the root (radicand promoted), and the subscript (dies, base stays) all confirmed, at depth. The asymmetry vs D5 is INTENDED: deleting from outside kills the content; deleting from inside at the □ unwraps and keeps the surviving content.
- **D7 — Function deletion: inward chain + head swap.** The movable closing paren deletes first, then char-wise inward through the argument; the emptied FIRST argument shows □; BS at that □ deletes the ENTIRE function. **OA-fn-args:** arguments BEYOND the first get NO □ — an emptied later argument renders bare and the next BS collapses it with its comma (`sin(x,y|)` → `sin(x,|` → `sin(x|)` → `sin(|□)` → gone). **D7b (OA-sinarg-merge):** BS at the argument start (immediately after the head) deletes the entire atomic head `sin(` — content and closing paren survive (`sin(a+b)` → `|a+b)`); the D7b trigger fires at the argument-content-start landing; payloads land on the outer row seam. **OA-rehead:** the head-less fence pair is a re-typing surface — letters seed a new head symbol at the pair's start, and `(` re-binds the whole pair as one fenced function with the waiting `)` as its close (`|a+b)` + `cos(` → `cos(a+b)`); undo unwinds the whole re-heading.
- **D8 — Groups delete letter-wise through the content phase:** the movable closing paren first, then the content character by character; no highlight step, no special confirmation.
- **D9 — The emptied group shows □, and BS there deletes the WHOLE group** (both fences in one stroke). Group and function deletion converge at the empty point; they differ only in that a group's fences are plain characters while a function's head is atomic.
- **OA-radical-strip.** BS at the radicand start strips the radical glyph; the content promotes inline at the root's position with the caret in front; an mroot's index content dies with the glyph.
- **OA-fence-flank deletion.** Fence glyphs delete as movable tokens from their adjacent stations: `1/(a+b|)` + Del → `1/(a+b|`; `1/(a+b)|` + BS → `1/(a+b`; `1/|(a+b)` + Del removes the open paren; BS at the left-of-`(` station = the ordinary left-consume rule.
- **OA-promote-border (2026-11-11, micro-fix session; source: the owner's banked B-33-family note — the caret "should be in front of the fraction"; log rec-mwcb8j6u-7).** When a glyph removal (BS dangling glyph / OA-del-glyph forward Del) unwraps a row to a single surviving cell, a flankable structure promoted to a bare ROOT or SLOT position lands at its border/flank station (`node` caret with `side`, per OA-lone-root-stations / the slot-boundary flank) — in front of / behind the structure — never inside its first slot (the pre-fix landing dived into the fraction's numerator). Promoted tokens keep the entry-station landing. Labels: D2, OA-del-glyph, OA-lone-root-stations, OA-flank-stations. **Amended 2026-11-13 (OA-promote-row-end, rec-mwe11hta-1):** a promoted ROW payload at a bare root/slot lands at its own row-border station (`rowEndStation` — the seam behind a trailing structure, e.g. `row [] #2` after collapsing `add(add(1,·√50),null)`), never dived into the trailing structure's interior (the radicand dive — the next BS there must fire the D5 highlight). Labels: D2, OA-promote-border, OA-visual-trumps, D5.

## Undo/Redo (U)

- **U1 — The undo unit.** Non-typing edits = one unit per keystroke. Typing runs COALESCE into deterministic bursts — NO timing threshold; a run closes at any non-typing action (structure key, Backspace, arrow, click). **OA-undo-burst:** the typing run BREAKS at every OPERATOR press — each operator press is its own unit, consecutive operators never coalesce (`a++b` = four units); parens, comma, dot, and Space keep coalescing into the text run (the `cos(` rebind stays one unit; the T5 conversion `(` stays its own unit). Undo restores the pre-unit tree AND caret byte-exactly; redo replays the unit and re-logs one entry; any new edit clears the redo stack.
- **U2 — Structure creation/deletion are single units:** one undo unwinds a structure creation including the node grab; one undo restores a highlighted-then-deleted structure whole (the red highlight is transient UI, not a unit).
- **U3 — Redo mirrors undo** (Ctrl+Shift+Z / Ctrl+Y).
- **U4 — Empty undo/redo stacks: silent no-ops.**
- Movement ops NEVER enter the undo log. The run log entry shape is runtime-only, never serialized.
- **OA-closeparen-exit.** Completing a fence by retyping the close paren lands the caret immediately AFTER the completed group, INSIDE the enclosing structure (the denominator's content end when the completed group sits in a fraction's denominator) — never right of the enclosing structure.

## Special keys (K)

- **K1 — Home/End: local first, then ITERATIVE outward.** Jump to the start/end of the current row/slot; pressed again at that boundary, escalate one level DIRECTLY to the enclosing row's start/end (one level per press), iterating to the formula start/end. Never dives into a sibling slot. Ctrl+Home/End deliberately unbound.
- **K2/K3 — The blur-commit family.** Enter/Tab/Escape: settle + discard pending/highlight + close the run + return the envelope, then blur. The post-blur behavior (new row / next cell / plain persist) is the HOST's convention, not Integral's. **S-106:** undo history across blur is Integral-agnostic — the host decides resume vs. discard; the demo discards the history and preserves the caret on resume.
- **Rejection pattern:** rejected keys are SILENT no-ops (second dot, formula-end arrows, empty-stack undo, forbidden adjacency input). A fromJSON gate rejection (e.g. an invalid mroot □-index shape) leaves the tree a silent no-op, classified into the controller's rejection readout; the typing surface drops the `mroot` flag when the index fills.

## Assignment — the `=` key (A, ruled 2026-11-11; the 12th node class `assign`, additive, envelope stays v1)

- **A1 — `=` inserts EAGERLY at the root row (the unit-style trigger).** Typing `=` at any caret position in the root row — mid-row, offset 0, token interiors (symbols AND numbers), from the empty formula — splits EVERYTHING: all content left of the caret becomes the assign node's LHS slot, all content right of the caret becomes the RHS slot; zero insertion-time validation of either side (T1 text-editor parity — `=` inserts wherever `+` inserts; the both-halves uniform reading per OA-both-halves: at `a+b|c` the WHOLE `a+b` is the LHS, not the preceding node; at `12|3` the number halves split; at offset 0 the LHS starts empty). Caret at the RHS start (the after-the-glyph position); from the completely empty formula: both slots □ with the caret in the LHS (the S-025 A template); at offset 0 with content: □ LHS + the content in the RHS, caret at the RHS start. Insertion + split + grab = ONE op = one undo unit, reverting to the unsplit row. The S-051/S-104 unit mechanism is the governing analogy for the LHS: classification is continuously re-derived from content on every change, both directions, never frozen. **Implementation notes (judgment calls, live-check flagged):** a pair-gap station (legal seam or illegal two-station edge) splits at the caret like any root-row position — the gap dissolves into the two slots (OA-seam-family (5) only requires gaps never block input); a pending null cell of the root row splits at the caret's index (the null goes right); a unit/sub token station splits whole at its edges and no-ops at interior label offsets; the RHS-start caret is the slot-boundary flank in front of a container RHS, else the content's left entry (token offset 0 / row dive), else the rhs □. **Flagged live-check item:** the offset-0 caret placement (with content right of the caret) is ruled at the RHS start per the OA-both-halves uniform reading — may flip to the LHS at the live check (`□=content` with the caret before the □ is the text-editor analog).
- **A2 — the LHS is freely editable content of any shape (ruled against any freezing).** Full in-token mechanics (T3 glue/split at any offset incl. digit-glue — `x1` is a legal symbol — letter-wise D1/D3 deletion), multi-node LHS content is a normal storable state while it lasts, rename at any time, never atomic (unlike a function head). Autosuggest (future feature) suggests available variables but never gates the input.
- **A3 — empty slots render □** (both renderers, the T7 split reading): `□=□` from empty, `□=rhs` at offset 0, `x=□` after conversion; □ persists while empty regardless of caret position (S-027 pattern). BS at an RHS start/□ = the A4 glyph rule.
- **A4 — the `=` glyph is a binding glyph.** BS/Del at it removes the glyph; the LHS and RHS content splice back together into one plain row at the assign's position (the insertion undone); the one undo unit per A1 covers it. Splice mechanics — the `=` junction is always a GAP, never an operator (rec-mwcq61uh-0: an explicit op-row side absorbing the other side as a cell manufactured a `+` where the `=` was): an explicit op-row side pairs its EDGE cell with the other side, nested in place (`a+b=c` + BS at the RHS start → `a+(b c)` implicit pair, caret at the gap's right edge; only a further BS at that gap merges the two symbols per the merge table → `a+bc`); two implicit same-op rows concatenate and a lone implicit row absorbs the other side as a cell (their junction is already an implicit seam); two non-row sides fuse per the OA-seam-family merge table (num-num digit concatenation `12=3`→`123`, sym-num digit-glue `x=5`→`x5`, sym-sym letter glue) and otherwise bond into an implicit pair; one empty side promotes the other; both empty → outright death. BS triggers: the RHS start stations (rhs □ slot, rhs token offset 0, rhs row seam 0, the rhs content's left flank) — and, as a judgment call, the LHS □ too (the splice with one side empty coincides with the D6 unwrap-promote). Del mirrors at the LHS end (token end / row end / container right flank). Clicks: the glyph maps to the shared gap between the slots, halves per OA-glyph-click-halves (left half → lhs end, right half → rhs start).
- **A5 — `=` fires only at the root row; assignment-ness is an EVAL STATE, not a structure flip.** Once the assign exists, every caret sits inside its slots → a further `=` press is a silent no-op: nesting and chaining are impossible BY CONSTRUCTION (no insertion-time refusal list exists). **isEvaluable = the assign at the ROOT + the LHS exactly one bare SymbolNode with non-empty name + the RHS evaluable.** Every other LHS shape — empty, number, multi-node row, group, structure, unit — = DECLINED EVALUATION ("no harm done"): storable, renders, error annotation, the node persists — NO structural dissolve; assignment-ness flips live↔declined continuously with the LHS content, like unit-ness flips with the letter run. Chained assignment (`x=y=5`) = a possible addition, not this session. An armed dead-^ pending + `=` **discards** the pending (the OA-one-shot ordinary-input path — an exponent never receives `=`; the pre-ruling "resolve" was a settle-machinery artifact; T8 amended accordingly).
- **A6 — AST + eval contract.** The 12th node class `assign` (additive; JSON envelope stays v1): the LHS and RHS slots each hold ANY single expression node or null (empty); fromJSON validates shape, not identifier validity (assignment-ness lives in isEvaluable); toMathNode() projects mathjs's AssignmentNode (standalone parity; the declined shapes refuse per the existing structural gate — and the projection throws on them too, like the implicit-row refusal); toMathML renders `lhs = rhs` with □ for empty slots. Zero consuming-app references — the consumer reads the LHS as the definition and the RHS as the value from the same JSON.
- **A7 — explicitly out of Integral scope:** the trailing `=` (inline result display) and `= unit` (result-unit override) = consumer display behavior over the stored AST; function-signature LHS (`f(x) = …`) = a later additive variant; equality/relational operators = later with the if-statement family.
- **Nav profile (judgment calls, live-check flagged):** `assign` = slots `['lhs','rhs']` with horizontal edges lhs↔rhs across the glyph zone (the pow chain pattern), NO vertical edges (inline single-baseline layout — up/down climbs to the parent like a row), no enterRight override (defaults to rhs), and no flank/border `side` stations on the assign itself (not flankable — it renders as an inline row whose extent is its content's).

## Evaluation + storage (the projection layer)

- **S-098 — number-number adjacency is FORBIDDEN.** Two adjacent number nodes without an operator are storable as an editing state; evaluation FAILS while the state persists. Visual hint (OA-seam-family, supersedes the earlier quieter tint): the `.integral-seam` carrier renders WIDE and RED between the nodes — an error state at a glance. The same wide red carrier marks EVERY illegal implicit pair (symbol-before-X, fn/unit-before-X, group|num too); LEGAL pairs render glyph-less with plain spacing and NO marker, in both renderers (byte-parallel).
- **Juxtaposition evaluation.** A number before a symbol/group/structure (`5x`, `5(a+b)`) reads as implicit multiplication and EVALUATES; a GROUP before anything evaluates the same way. A symbol before anything REFUSES (`x3` name ambiguity, `x(…)` call ambiguity); function/unit-before-X refuse. Number-number forbidden (S-098). Representation: glyph-less adjacency stores as a multiply row carrying an additive `implicit: true` marker (renders without the × glyph; one marker per row; never evaluation semantics). **OA-mixed:** juxtaposition never shares an n-ary row with explicit glyphs — the glyph-less pair materializes as its own implicit-multiply subrow nested in the explicit row (`5x|` + `*` → multiply[implicit{5,x}, null]); the same-op flattening rule NEVER flattens marker-carrying subrows into explicit parents (pinned both directions).
- **Empty-slot operator rows (math-style projection).** A glyph whose left cell is null applies unary to its right cell: leading `−` = negation, leading `+` = identity; a doubled operator acts on what follows (`2−−3` = 5, `a+b++c`); trailing-null, all-null, and double-null refuse. Editor states only — the editor never creates unary nodes; the walker's own unary nodes stay untouched.
- **Fence-state fields.** Unbalanced-fence states are storable and render; evaluation refuses them through the existing structural gate. No new evaluation rule.
- **Rendering split.** Empty 2D structure slots render □ (U+25A1); op-row null cells render bare; an empty subscript script renders □. The □ persists while its slot is empty, regardless of caret position.
- **Rendering contract.** The MathML is the visual contract: the editor's DOM must equal the string renderer's output (the parity pin); the seam marker carries explicit width/height/depth and the red error background (OA-seam-family).

## Paint rules (overlay-only — no engine state changes)

- **OA-seam-caret-height.** A seam station's caret paints at the height of its LEFT-adjacent element (`1+|1/2` → text height; `1+1/2|` → fraction height); interior row seams anchor at the separator glyph; fallback at row starts = the current element's height. Explicitly unwanted: a caret as tall as a fraction while standing LEFT of it.
- **OA-after-structure-shift.** The after-structure station paints with a small right shift (2px), so it is distinguishable from the interior-end station sharing the same horizontal space.
- **OA-unit-seam-paint.** The unit-seam caret paints MID-WAY between the value and the label (both seam states). **Generalized (OA-seam-family (1)):** every LEGAL implicit-pair seam (token edge or row gap) paints midway at the left cell's height; the illegal two-station gap keeps its two edge stations, each painting at its own edge.
- **OA-token-glyph-paint (2026-11-13, rec-mwes18zj-1).** An in-token caret (num/sym token, unit label, sub label) paints at the per-CHARACTER boundary — a collapsed Range at the offset over the token's own text node — whenever the platform measures range rects; the linear interpolation over the token's extent is only the no-layout fallback (jsdom). The seam-midway paints (OA-unit-seam-paint / OA-seam-family (1)) are unchanged. Labels: N1, paint, OA-visual-trumps.
- **OA-empty-caret (2026-11-13, rec-mwes87dv-3).** The empty formula's caret is VISIBLE: when the empty `<math>` rect is degenerate (0 height), the anchor falls back to the computed font metrics — height = the math element's computed font-size, top = its rect top with the em box centered in the line box ('normal' line-height ≈ 1.2em) — at the math element's left edge, where the first glyph would land. A math rect with real height keeps the plain anchor. Labels: paint, D4, C5.
- **OA-caret-focus (2026-11-13, rec-mwes87dv-3).** The overlay caret div paints ONLY while the editor container is focused: hidden from the initial render until focus, hidden again on blur (the keydown handler already acted only while focused; the caret paint now matches). Labels: paint, K2/K3.
